# 基准测试方法

## 这个数字代表什么

报告中的 **88.47 tokens/s**，是 Cv-MemoEngine Hot66/128K 配置在并发 19 时的输出吞吐。它表示服务在正式测量窗口内生成 completion token 的速度，不是单个算子的速度，也不是客户端界面显示速度。

## 测试工具与负载

- 测试工具：SGLang serving benchmark（`bench_serving`）
- 服务接口：SGLang HTTP serving 接口
- 数据集：固定长度 random 请求
- 输入长度：1,024 tokens
- 输出长度：1,024 tokens
- 请求速率：无限制，由并发档位控制请求数量

## 并发矩阵

正式测试使用十个并发档位：`C1、C3、C5、C7、C9、C11、C13、C15、C17、C19`。

每个档位测试 4 轮，每轮必须完整成功，因此并发矩阵共包含 40 个正式 case。

| 并发 | 输出吞吐 | 总吞吐 |
| ---: | ---: | ---: |
| 1 | 52.93 tokens/s | 105.87 tokens/s |
| 3 | 76.32 tokens/s | 152.63 tokens/s |
| 5 | 79.09 tokens/s | 158.19 tokens/s |
| 9 | 86.61 tokens/s | 173.21 tokens/s |
| 13 | 87.86 tokens/s | 175.73 tokens/s |
| 19 | **88.47 tokens/s** | 176.94 tokens/s |

C19 数值是 4 轮成功结果的算术平均，观测范围为 88.08–88.68 tokens/s，标准差为 0.278 tokens/s。

## 指标定义

### 输出吞吐

`输出吞吐 = 实际生成的输出 tokens / 正式测量时长`

测量时长包含正式请求的生成过程。预热以及 case 之间的计划停顿不计入正式测量窗口。

### 总吞吐

`总吞吐 = (输入 tokens + 输出 tokens) / 正式测量时长`

总吞吐同时反映输入处理和输出生成能力，适合做整体容量评估；比较解码性能时仍应使用输出吞吐。

### TTFT

TTFT（Time To First Token）是从请求被服务端接收，到返回第一个输出 token 的耗时，包含该请求的调度和 prefill 工作。

### TPOT

TPOT（Time Per Output Token）是第一个 token 之后，后续输出 token 的平均生成间隔。TPOT 越低，连续输出越平滑。

## 长序列测试方法

长序列测试使用单并发。每个测试点的输入长度与输出长度相同，共有 83 个成功长度点，范围为 100–17,700 tokens。每个长度点运行 2 次，共完成 166 次长序列运行。

每个长度点记录输出吞吐、总吞吐、TTFT、TPOT 和端到端耗时，发布值取成功运行的算术平均。

| 输入/输出长度 | 输出吞吐 | TTFT | TPOT |
| ---: | ---: | ---: | ---: |
| 100 / 100 | 40.73 tokens/s | 291 ms | 21.28 ms/token |
| 500 / 500 | 53.13 tokens/s | 441 ms | 17.86 ms/token |
| 1,300 / 1,300 | 52.88 tokens/s | 722 ms | 18.33 ms/token |
| 5,100 / 5,100 | 50.22 tokens/s | 2,625 ms | 19.39 ms/token |

## 为什么 128K 容量验证和长序列性能是两个口径

- **128K 容量验证**：验证运行时能否接近上下文容量上限。测试使用一次 131,072-token 输入和较短的 256-token 输出，结果用于说明容量边界。
- **长序列性能测试**：验证吞吐和延迟如何随输入规模变化。测试使用 83 个长度点，并且每个点的输入、输出长度相同。

容量验证不是 128K/128K 吞吐成绩，83 点长序列矩阵也不代表所有上下文和输出组合都已测试。分开报告可以避免误解。

## 计时探针

工程探针用于解释性能，不替代正式 benchmark：CPU 专家阶段、设备时间线、H2D、MCCL、事件等待、图重放、CPU 内存带宽、温度和功耗均单独记录。
